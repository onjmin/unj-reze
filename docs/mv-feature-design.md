# ミュージックビデオ(MV)機能の設計

画像・ドット絵・MMLを組み合わせて「音楽そのものを主役にした動画」を投稿する機能。
ゲーム機能と同じく **プリセットを選んで中身を差し替える** 体験に寄せてあり、
AviUtl のような自由タイムラインは意図的に持たない。

- 型定義: [lib/mv-config.ts](../lib/mv-config.ts)
- 描画: [lib/mv-engine.ts](../lib/mv-engine.ts)
- 音: [lib/mv-audio.ts](../lib/mv-audio.ts)
- プリセット: [components/mv-presets/](../components/mv-presets/)
- 編集UI: [components/MvMaker.tsx](../components/MvMaker.tsx)
- 再生: [components/MvPlayer.tsx](../components/MvPlayer.tsx) / 埋め込み: [components/MvBox.tsx](../components/MvBox.tsx)

---

## 1. 時間軸はMMLだけ

MVの時間はすべて `@onjmin/dtm` の再生ステップ（1小節=192ステップ）から導出する。
`MvPlayer` は `onTick(step)` を音声クロックとして受け取り、rAF はティック間を線形補間するだけ。
描画が重くても音とズレない。

外部音源（YouTube等）は使えない。ノートが読めないとビジュアライザ・歌詞・図形の同期が
成立しないため、音源はMMLに限定している。

### 音の出し方（3モード）

| モード | 実体 | 用途 |
|---|---|---|
| `light` | `playMML`（内蔵矩形波シンセ） | ダウンロード無しで即再生 |
| `soundfont` | `studio.play`（SoundFont） | 楽器音がちゃんと鳴る。歌詞トラックも楽器として鳴る |
| `soundfontKoe`（既定） | `studio.play` ＋ `playSingingMML` | 楽器＋koe歌声。いちばん元の曲に近い |

`soundfontKoe` は楽器と歌声を**別々の再生として同じ AudioContext 上で重ねる**。
`@onjmin/dtm` の正典（`mountMmlPlayer`）は歌詞トラックの楽器発音をスキップするので、
楽器側へ渡すMMLからは歌詞トラックの演奏トラックを落とす（`stripLyricPerformanceTracks`）。
これをしないと歌と楽器が二重に鳴る。

## 2. レイヤーは7種だけ

| 種類 | 何をするか |
|---|---|
| `image` | 画像・ドット絵・歩行グラ。`repeat` で1レイヤーのまま何体も並べられる |
| `text` | 文字（縦書き対応） |
| `visualizer` | `pianoRoll` / `stepGrid` / `rings` / `bars` |
| `lyrics` | MMLの歌詞トラック(`@@n`)から自動同期、または小節指定の手入力 |
| `shape` | 音に反応する図形。モジュレータで複雑な動きを作る |
| `effect` | 画面全体の演出（フラッシュ・反転・ゆれ・ズームパンチ・ストロボ・周辺減光） |
| `chordBar` | 画面下のコード進行バー |

動きは `MvMotion` の enum から選ぶ（数値キーフレームは無い）。
時間軸の分岐は「小節番号で区切ったセクション」だけで、レイヤーは表示するセクションIDを持つ。

### 画像の登場のしかた（`MvEntrance`）と反転

`image` レイヤーは既定では「セクションに入った瞬間パッと出る」。`MvImageLayer.entrance` を付けると、
**上下左右からのスライドイン**と**フェードイン**を組み合わせられる（`from` と `fade` は独立なので、
スライドのみ／フェードのみ／左からフェードイン、が全部作れる）。`beats` 拍かけて easeOutCubic で
定位置・不透明へ寄る。`entrance` 未指定＝従来どおり瞬時に出現。

演出の起点は `layerAppearBar()`——**そのレイヤーが出てきたセクションの頭**。
連続するセクションにまたがって表示されるレイヤーは連続の先頭が起点になる。
場面が変わるたびにやり直すと、出っぱなしの絵が何度も飛び込んでくるため。

`flipH` / `flipV` は描画時だけの鏡像。占める矩形は変えたくないので描画矩形の中心で反転し、
`frame` の枠は反転しない。歩行グラの向きを変えたり、同じ絵を左右で向かい合わせたりに使う。

### 歌詞トラックの選択

`parseLyrics(mml)` は `Map<trackId, LyricTrack>` を返す。曲によっては歌詞トラックが複数ある。
**全部出すと画面が文字で埋まる**ので、`MvLyricsLayer.trackId` で1本だけ選ぶのが既定。
明示的に `'all'` にしたときだけ全部出す。

歌詞はMML内の定義に縛られない。「この歌詞を手入力にコピーして編集する」でMML由来の行を
`source:'manual'` の `lines` へ写せるので、文言・タイミングをあとから自由に直せる
（写した時点でMML側への追従は切れる）。

### ピアノロールの見せ方

`MvVisualizerLayer.projection` で3通り。

- `flat` … 真横から見た平面（従来）
- `perspective` … MIDITrail のような立体。時間を横（右が未来）、音高を縦、**トラックを奥行きのレーン**に
  割り当てた厚みつきの板が右から左へ流れる。`MvView`（見下ろし/回り込み/傾き/画角/レーン奥行き/厚み）で
  視点を決め、画家のアルゴリズムで奥のレーンから手前へ描く。`glow` 時はノートの頭で波紋が出る。
  ※初期実装は時間を奥行きに取るトンネル型だったが、参考動画のようには見えず置き換えた。
- `circular` … 音域を円周に、時間を半径方向に巻きつける。`MvRing`（内径/円弧角/回転）で形を決める。

## 3. 音→絵をつなぐモジュレータ

`shape` レイヤーの肝。基準値に対して「何を」「どこに」「どう混ぜるか」を1行ずつ重ねる。

```
値 = 基準値
各モジュレータについて（上から順に）:
    値 = 値 op (source(0..1) × amount)
```

- source: `beat` / `bar` / `time` / `trackEnergy` / `trackOnset` / `trackPitch` / `constant`
- target: `size` / `rotation` / `opacity` / `x` / `y` / `thickness` / `sides` / `count`
- op: `add` / `sub` / `mul` / `div`

`trackEnergy` などはトラック指定できるので、**パートごとに別の図形を反応させられる**。
合成モード（`blend`）で加算・乗算・差の絶対値などを選べるため、単純な形の重ねがけから
複雑な模様が作れる。

`count` > 1 のとき `stagger` を入れると、1個ごとにモジュレータの評価を遅らせて
「端から順に反応が伝わる波」が作れる。

内蔵の形で足りない複雑な形は `form:'path'` で持ち込める。SVGマークアップを貼り付けると
`d` 属性と `viewBox`（`pathBox`）を自動で取り込み、複数パスは1つの形として重ねて
evenodd で塗る（重なりが穴になる）。パーツごとに別の動きをさせたいときは、
パスをレイヤーに分けてそれぞれへモジュレータを付ける。

### 演出（effect）の発火タイミング

`trigger` は `always`/`beat`/`bar` の周期発火に加え、`bars`（小節番号の配列 `MvEffectLayer.bars` で
**指定した小節の頭だけ**）が選べる。「サビ頭だけフラッシュ」のような決め打ちはこれを使う。
なお `MvPlayer` の補間 step は再生中単調増加にクランプしてある——ティック到着で step が巻き戻ると
拍境界をまたぎ直してフラッシュが二重発火するため。`timeSec` も step から導出する。

> **注意**: `div` は分母を `MIN_DIVISOR`(0.05) でクランプしてある。
> `beat` のように0へ近づく値で割ると図形が発散して画面を覆い尽くすため。
> 描画半径も `MV_W * 2` で頭打ちにしている。

## 4. コード進行バー

`utau-kit` の `src/tools/chord-progression-animation-tool.html` と同じ考え方で、
**キーに対する度数**から色相を決める（`MV_DEGREE_HUE`）。スケール外のコードは彩度を落とす。
いま鳴っているブロックだけ `activeColor` で塗る。

コードは `{ bar, label }` の配列として手で並べる。次のコードが始まるまでが1ブロックの長さ。

## 5. プリセットと参考動画の対応

| プリセット | 参考動画 | 使っている機能 |
|---|---|---|
| ジオメトリック | `C.mp4` | 呼吸する背景、波紋、図形＋モジュレータ、トラック別反応、ノート連動フラッシュ |
| シーケンサ | `次日朝夢(再現).mp4` / `x0o0x_.mp4` | 大きなステップ格子、縦書き歌詞の積み上げ、`stagger` の線、`repeat` の群れ、キックで画面ゆれ |
| ピアノロール | `[Touhou Style Arrangement]…mp4` | イントロ（ロールのみ）→本編入りで一発フラッシュ→静止画＋タイトル/クレジットが出続ける |
| ドット絵ステージ | `_.mp4` | 枠付きスプライト窓、ステップ格子、縦書き歌詞（残像）、セクションでの場面転換 |
| ステージ整列＋コード進行 | `ことりがそらへとおちてゆく.mp4` | キャラの整列、歌詞の帯、コード進行バー |

プリセットは著作物を同梱しない。仮素材は `public/assets/rpgen/char/` の内蔵歩行グラのみで、
背景・キャラはユーザーが差し替える前提（各プリセットの `swapHint` に明記）。

## 6. 編集UIの方針

**かんたん / くわしい** の2モード（既定はかんたん）。MMLエディタの シンプル/上級者 と同じ考え方で、
はじめて触る人がいきなり全設定に出会わないようにする。

- かんたん … 「見本」「曲」「見た目」の3タブ。見本を選ぶ → 曲を入れる → 絵を差し替える、で完成する。
  画像レイヤーは「見た目」タブに一覧で出るので、レイヤー編集に入らなくても差し替えられる。
- くわしい … 「レイヤー」「歌詞」「場面」が増える。3D視点・合成モード・モジュレータなどの
  込み入った設定は `Details`（たたみ込み）の中に入れて、既定では閉じておく。

モバイル対応:
- 入力欄はラベルを上に置いて全幅・高さ36px以上（狭い画面で横並びにすると両方潰れるため）
- 編集モード切替はヘッダーに置く。タブ行（横スクロール）に入れると画面外へ流れて押せなくなる
- 375px 幅で横スクロールが発生しないことを確認済み

## 7. 転送量

`mvs.manifest` は **一覧クエリで絶対に SELECT しない**（[docs/NEON_EGRESS.md](./NEON_EGRESS.md)）。
`getMvsByIds` はサムネ用の背景URLだけをSQL側で抜き出す。
manifest 本体は展開時に `/api/mvs/[id]` で取りにいく。
